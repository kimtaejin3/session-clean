# sclean 제품 요구사항 문서(PRD)

| 항목 | 내용 |
|---|---|
| 제품명 | sclean (Session Clean) |
| 버전 | v0.1 |
| 문서 상태 | 구현 준비 |
| 작성일 | 2026-08-26 |
| 1차 플랫폼 | macOS 터미널 |

## 1. 제품 요약

`sclean`은 여러 프로젝트에 쌓인 Claude Code 세션을 프로젝트별로 확인하고, 규칙 기반 추천을 이용해 한 번에 안전하게 정리하는 로컬 터미널 UI(TUI) 도구다.

사용자는 `sclean` 하나만 실행한다. 세션 선택, 추천 기준 변경, 휴지통 이동, 완전 삭제, 복원과 휴지통 비우기는 모두 TUI 안에서 수행한다. 네트워크 연결이나 계정은 필요하지 않으며 세션 내용은 외부로 전송하지 않는다.

## 2. 문제 정의

Claude Code를 여러 프로젝트에서 사용하면 `~/.claude` 아래에 프로젝트별 세션과 관련 데이터가 계속 쌓인다. Claude Code의 세션 선택기는 과거 세션을 찾고 다시 여는 데는 유용하지만, 여러 프로젝트의 불필요한 세션을 선별하여 일괄 정리하는 흐름은 제공하지 않는다.

사용자는 다음 문제를 겪는다.

- 프로젝트마다 쌓인 세션을 하나씩 확인해야 한다.
- 오래된 세션과 필요한 세션을 빠르게 구분하기 어렵다.
- 삭제된 프로젝트나 짧게 종료된 세션도 계속 남는다.
- 세션 파일만 직접 지우면 관련 데이터가 남거나 복구가 어려울 수 있다.
- 완전 삭제는 실수 위험이 있어 일괄 실행하기 불안하다.

## 3. 대상 사용자

### 주 사용자

- macOS 터미널에서 Claude Code를 사용하는 개인 개발자
- 여러 프로젝트를 오가며 Claude Code 세션을 자주 생성하는 사용자
- 세션을 직접 찾아 지우는 작업이 번거롭지만 클라우드 동기화나 팀 협업 기능은 필요하지 않은 사용자

### 사용 상황

- 몇 주 또는 몇 달마다 쌓인 세션을 한꺼번에 정리할 때
- 삭제한 프로젝트의 세션 흔적을 제거할 때
- 짧게 실패하거나 중단된 세션과 하위 에이전트 세션을 정리할 때

## 4. 제품 목표

1. 여러 프로젝트의 Claude Code 세션을 한 화면에서 파악할 수 있게 한다.
2. 설명 가능한 규칙으로 정리 후보를 자동 추천한다.
3. 선택한 세션과 관련 데이터를 한 번에 정리한다.
4. 휴지통과 복원 기능으로 실수 위험을 낮춘다.
5. 프로젝트 소스 파일을 건드리지 않고 모든 작업을 로컬에서 수행한다.

## 5. 비목표

v0.1에서는 다음 기능을 제공하지 않는다.

- Claude Code 세션 실행 또는 재개
- 실행 중인 여러 에이전트의 실시간 모니터링
- AI를 이용한 세션 내용 분류
- 백그라운드 자동 정리 또는 예약 실행
- 클라우드 동기화, 계정, 팀 협업
- 네이티브 macOS GUI
- Codex, OpenCode 등 다른 코딩 에이전트 지원
- 자동 업데이트와 Homebrew 배포
- 프로젝트·세션 검색
- Claude의 공유 paste cache, 전역 plan, telemetry 정리

## 6. 핵심 원칙

### 안전 우선

- 시작 시 추천 세션을 자동으로 선택하지 않는다.
- 실행 전 대상 파일, 세션 수, 용량과 정리 방식을 보여준다.
- 프로젝트 소스 경로는 읽기 확인 외에는 접근하지 않는다.
- 불확실한 세션은 추천하지 않는다.
- 복원 시 기존 파일을 덮어쓰지 않는다.

### 설명 가능한 추천

각 추천에는 `마지막 활동 후 92일 경과`처럼 사용자가 확인할 수 있는 이유를 표시한다. 점수나 AI 판단처럼 근거가 불투명한 추천은 사용하지 않는다.

### 로컬 전용

세션 데이터와 사용 행동을 외부로 전송하지 않는다. 계정, 인증, 원격 API와 텔레메트리를 포함하지 않는다.

## 7. 핵심 사용자 흐름

1. 사용자가 터미널에서 `sclean`을 실행한다.
2. 도구가 `~/.claude`를 읽고 프로젝트와 세션을 표시한다.
3. 사용자가 추천 이유를 확인하고 개별 세션 또는 추천 전체를 선택한다.
4. 사용자가 정리를 실행하고 `휴지통 이동` 또는 `완전 삭제`를 선택한다.
5. 도구가 대상 파일과 예상 정리 용량을 다시 보여준다.
6. 사용자가 확인하면 도구가 세션과 연결 데이터를 트랜잭션 방식으로 정리한다.
7. 결과 화면에서 성공, 건너뜀, 오류 항목을 확인한다.
8. 휴지통 화면에서 이전 작업을 선택해 복원하거나 영구 삭제할 수 있다.

## 8. TUI 정보 구조

### 8.1 세션 화면

기본 화면은 프로젝트 목록과 해당 프로젝트의 세션 목록으로 구성한다.

왼쪽 패널에서 프로젝트를 고르면 오른쪽 패널에 그 프로젝트의 세션만 표시한다.
두 패널은 각자 커서를 가지며 `←` `→`로 어느 쪽을 조작할지 정한다.

```text
┌ Projects 1/3 ──────────────┐┌ shop-api — 세션 8 ───────────── [Trash: 12] ┐
│▶ shop-api      추천 8      ││  [ ] ★ 92일 전  로그인 수정   마지막 활동… │
│  portfolio     추천 3      ││  [ ] ★ 61일 전  제목 없음     마지막 활동… │
│  old-admin     추천 6 경로없││  [-] ! 44일 전  분석 불가     세션 형식을… │
└────────────────────────────┘└─────────────────────────────────────────────┘
 ↑↓ 프로젝트  → 세션 보기  Space 전체선택  A 추천전체  D 정리  T 휴지통  F 기준
```

터미널 폭이 좁으면 두 패널을 나란히 두지 않고 현재 조작 중인 패널만 전체 폭으로 표시한다.

세션 행에는 가능한 범위에서 다음 정보를 표시한다.

- 선택 상태
- 마지막 활동 시각
- 세션 이름, 첫 프롬프트 또는 세션 ID
- 추천 여부와 추천 이유
- 세션 데이터 크기

### 8.2 정리 확인 모달

다음 정보를 표시한다.

- 선택한 프로젝트와 세션 수
- 이동 또는 삭제할 파일 수
- 예상 정리 용량
- 스캔 이후 변경되어 제외된 세션
- `휴지통 이동`과 `완전 삭제` 선택

완전 삭제는 추가로 `DELETE` 입력을 요구한다.

### 8.3 휴지통 화면

휴지통 작업을 정리 시각별로 묶어 표시한다. 사용자는 작업 전체 또는 개별 세션을 선택할 수 있다.

- `R`: 선택 항목 복원
- `X`: 선택 항목 영구 삭제
- `Enter`: 포함된 프로젝트, 세션과 원래 경로 확인
- `Esc`: 세션 화면으로 복귀

### 8.4 추천 기준 화면

TUI 안에서 다음 항목을 변경한다.

- 오래됨 기준: 기본 30일
- 짧은 세션 추천 사용 여부: 기본 켜짐
- 종료된 하위 에이전트 추천 사용 여부: 기본 켜짐
- 존재하지 않는 프로젝트 추천 사용 여부: 기본 켜짐
- 고아 데이터 추천 사용 여부: 기본 켜짐

변경한 기준은 `~/Library/Application Support/sclean/config.json`에 저장한다.
Linux에서는 XDG 관례에 따라 `~/.local/share/sclean/config.json`을 쓴다.

### 8.5 공통 조작

| 키 | 동작 |
|---|---|
| `↑` / `↓` | 현재 패널에서 항목 이동 |
| `→` | 선택한 프로젝트의 세션 목록으로 이동 |
| `←` | 프로젝트 목록으로 돌아가기 |
| `Space` | 선택·해제 (프로젝트 목록에서는 그 프로젝트 전체) |
| `A` | 추천 항목 전체 선택·해제 |
| `D` | 선택 항목 정리 |
| `T` | 휴지통 화면 |
| `F` | 추천 기준 화면 |
| `?` | 도움말 |
| `Q` | 종료 |

현재 화면에서 사용할 수 있는 핵심 조작은 하단에 항상 표시한다. 색상은 상태 구분을 보조할 뿐 유일한 표현 수단으로 사용하지 않는다.

## 9. 자동 추천 규칙

추천은 규칙별로 독립적으로 활성화하거나 비활성화할 수 있다. 하나 이상의 규칙을 충족하면 추천으로 표시한다.

### R1. 오래된 세션

- 마지막 활동 시각이 사용자가 설정한 기간보다 오래된 세션
- 기본 기준은 30일
- 표시 예: `마지막 활동 후 92일 경과`

### R2. 존재하지 않는 프로젝트

- 세션에서 확인한 프로젝트 경로가 현재 파일시스템에 존재하지 않는 경우
- 프로젝트 경로를 신뢰할 수 있게 확인하지 못하면 이 규칙을 적용하지 않는다.

### R3. 짧은 세션

- 사용자 메시지가 1개 이하이고 도구 실행 기록이 없는 세션
- JSONL을 정상적으로 분석한 경우에만 적용한다.

### R4. 종료된 하위 에이전트 세션

- Claude 데이터에서 하위 에이전트로 식별되는 세션
- 최근 변경 중인 하위 에이전트는 제외한다.

### R5. 고아 데이터

- 세션 대화 기록은 없지만 동일한 세션 ID의 작업, 환경 또는 디버그 데이터가 남은 경우
- 삭제 대상을 정확히 세션 ID로 연결할 수 있을 때만 적용한다.

### 추천 제외 조건

다음 조건에서는 자동 추천하지 않거나 정리를 차단한다.

- 세션 형식을 분석할 수 없음
- 프로젝트 경로의 신뢰성 있는 확인이 불가능함
- 현재 실행 중인 것으로 확인됨
- 스캔 이후 파일의 크기 또는 수정 시각이 변경됨
- 연결 데이터의 소유 세션을 확정할 수 없음

추천은 선택을 대신하지 않는다. 사용자가 직접 선택하거나 `A`로 추천 전체를 선택해야 한다.

| FR-13 | P0 | 스캔 이후 변경된 세션의 정리를 거부한다. |

| FR-15 | P0 | 알 수 없는 세션 형식을 안전하게 표시하고 추천에서 제외한다. |
| FR-16 | P0 | 프로젝트 소스 파일을 변경하지 않는다. |

충분하다고 판단했다. 나머지 ID는 추적을 위해 그대로 둔다. §5를 참고한다.

## 11. 데이터와 저장 구조

### 11.1 읽기 대상

v0.1은 다음 Claude 로컬 데이터 위치를 대상으로 한다.

```text
~/.claude/projects/
~/.claude/tasks/
~/.claude/todos/
~/.claude/sessions/
~/.claude/session-env/
~/.claude/teams/
~/.claude/file-history/
~/.claude/debug/
~/.claude/history.jsonl
```

실제 설치에서 존재하는 경로만 읽는다. Claude Code 버전에 따라 구조가 다를 수 있으므로 누락된 경로를 오류로 처리하지 않는다.

프로젝트 경로는 세션 기록의 `cwd`를 우선 사용한다. 이를 확인하지 못하면 Claude가 생성한 프로젝트 폴더명을 표시용으로 사용하되, 프로젝트 존재 여부 추천은 적용하지 않는다.

### 11.2 `sclean` 저장 위치

```text
~/Library/Application Support/sclean/     (Linux: ~/.local/share/sclean/)
├── config.json
├── sclean.log
└── trash/
    └── <시각>-<작업ID>/
        ├── manifest.json
        └── files/
```

`manifest.json`에는 다음 정보를 기록한다.

- 작업 ID와 상태
- 세션 ID와 프로젝트 경로
- 원래 파일 경로와 휴지통 내부 경로
- 파일 크기와 이동 시각
- 적용된 추천 이유
- 공유 기록 수정에 필요한 복원 정보

세션 대화 내용 자체를 별도의 데이터베이스에 복제하지 않는다.

## 12. 정리 트랜잭션

모든 정리 방식은 동일한 안전 절차를 사용한다.

1. 선택한 세션과 연결 파일을 다시 스캔한다.
2. 스캔 이후 변경된 세션을 제외하고 사용자에게 알린다.
3. 프로젝트 소스 경로가 대상에 포함되지 않았는지 검증한다.
4. 전체 작업 목록을 미완료 상태의 `manifest.json`으로 기록한다.
5. 세션 전용 파일을 `sclean` 휴지통으로 이동한다.
6. `history.jsonl`처럼 공유되는 파일은 백업 후 임시 파일에 수정하고 원자적으로 교체한다.
7. 모든 단계가 성공하면 manifest를 완료 상태로 변경한다.
8. 휴지통 이동을 선택했다면 작업을 보존한다.
9. 완전 삭제를 선택했다면 완료된 작업 폴더를 제거한다.

5~6단계에서 실패하면 이미 이동한 파일과 공유 기록을 원상 복구한다. 복구까지 실패하면 manifest와 로그를 보존하고 다음 실행에서 복구 화면을 우선 표시한다.

## 13. 복원 정책

- 원래 경로가 비어 있을 때만 복원한다.
- 동일 경로에 파일이 있으면 덮어쓰지 않고 해당 항목을 충돌 상태로 표시한다.
- 공유 기록은 현재 내용에서 동일 세션 ID가 없는 경우에만 복원 정보를 병합한다.
- 일부 항목에 충돌이 있으면 사용자가 충돌 없는 항목만 복원하도록 다시 선택할 수 있다.
- 복원 완료 후 빈 휴지통 작업 폴더를 제거한다.
- 휴지통은 자동 만료시키지 않으며 사용자가 TUI에서 직접 영구 삭제한다.

## 14. 오류 처리

| 상황 | 동작 |
|---|---|
| Claude 데이터 디렉터리가 없음 | 빈 상태와 Claude Code 세션을 찾지 못했다는 안내 표시 |
| JSONL 일부 행이 손상됨 | 읽을 수 있는 정보만 표시하고 추천 제외 |
| 파일 읽기 권한 없음 | 변경 없이 대상 경로와 권한 문제 안내 |
| 정리 직전 파일 변경 감지 | 해당 세션 제외 및 이유 표시 |
| 파일 이동 실패 | 작업 전체 롤백 |
| 공유 기록 교체 실패 | 작업 전체 롤백 |
| 실행 중 강제 종료 | 다음 시작 시 미완료 manifest 감지 및 복구 제안 |
| 복원 경로 충돌 | 덮어쓰기 없이 충돌 표시 |
| 터미널 크기가 너무 작음 | 필요한 최소 크기 안내, 데이터 변경 없음 |

오류 메시지는 문제, 변경된 항목 여부, 사용자가 할 수 있는 다음 행동을 함께 보여준다.

## 15. 비기능 요구사항

### 성능

- 일반적인 Apple Silicon Mac에서 2,000개 세션을 3초 안에 첫 화면에 표시한다.
- 스캔 중에도 진행 상태를 표시하며 TUI 입력이 멈춘 것처럼 보이지 않아야 한다.
- 세션 전체 내용을 메모리에 계속 보관하지 않는다.

### 안정성

- 삭제와 복원은 반복 실행해도 이미 완료된 작업을 중복 적용하지 않아야 한다.
- 경로 검증을 통과하지 못한 파일은 이동하거나 삭제하지 않는다.
- 공유 파일 변경은 임시 파일과 원자적 교체를 사용한다.

### 호환성

- 1차 검증 환경은 Apple Silicon macOS다.
- Linux(x64/arm64)도 지원한다. Windows는 유닉스 전용 파일시스템 API를 써서 범위 밖이며 WSL로 대체한다.
- Claude 내부 JSONL 형식이 바뀌어도 앱이 종료되지 않고 해당 세션을 `분석 불가`로 처리해야 한다.
- Claude 데이터 위치와 필드 처리는 한곳에서 교체할 수 있어야 한다.

### 개인정보 보호

- 네트워크 요청을 하지 않는다.
- 텔레메트리를 수집하지 않는다.
- 로그에는 프롬프트 본문을 기록하지 않는다.
- 설정과 휴지통은 사용자 Mac에만 저장한다.

### 사용성 및 접근성

- 핵심 흐름은 키보드만으로 완료할 수 있어야 한다.
- 색상 없이도 텍스트와 기호로 상태를 구분할 수 있어야 한다.
- 파괴적 작업의 확인 문구와 선택 상태를 명확히 표시한다.

## 16. 검증 계획

테스트는 실제 사용자 `~/.claude`가 아닌 임시 디렉터리의 Claude 데이터 fixture를 사용한다.

### 필수 자동 검증

1. 프로젝트와 세션 탐색 및 그룹화
2. 다섯 가지 추천 규칙의 일치·불일치
3. 손상되거나 알 수 없는 JSONL의 안전한 처리
4. 개별 선택과 추천 전체 선택
5. 여러 세션의 일괄 휴지통 이동
6. 완전 삭제 확인 절차
7. 중간 파일 이동 실패 시 전체 롤백
8. 공유 기록 변경 실패 시 전체 롤백
9. 휴지통 세션 복원
10. 복원 경로 충돌 시 덮어쓰기 방지
11. 스캔 이후 변경된 세션의 정리 차단
12. 프로젝트 소스 경로가 대상에 포함되지 않음을 검증
13. 미완료 manifest 감지와 복구

### 수동 승인 시나리오

1. 세션을 휴지통으로 옮긴 뒤 Claude Code 세션 목록에서 사라지는지 확인한다.
2. 휴지통 세션을 복원한 뒤 Claude Code에서 다시 열 수 있는지 확인한다.
3. 추천 기준을 TUI에서 변경하고 다음 실행에도 유지되는지 확인한다.
4. 2,000개 fixture 세션에서 첫 화면 표시 시간을 측정한다.
5. 정리 전후 프로젝트 소스 트리의 변경이 없는지 비교한다.

## 17. 출시 승인 기준

다음 조건을 모두 충족하면 v0.1을 공개할 수 있다.

- 처음 사용하는 사람이 별도 문서 없이 1분 안에 추천 세션을 확인하고 휴지통으로 이동할 수 있다.
- 휴지통 이동 후 세션이 Claude Code 목록에서 보이지 않는다.
- 복원 후 해당 세션을 Claude Code에서 다시 열 수 있다.
- 실패 주입 테스트에서 일부 파일만 정리된 상태가 남지 않는다.
- 프로젝트 소스 파일을 읽기 확인 외에는 변경하지 않는다.
- 네트워크 없이 모든 핵심 기능이 동작한다.
- 필수 자동 검증과 수동 승인 시나리오가 모두 통과한다.

## 18. 제품 검증 지표

v0.1의 목적은 대규모 수익화가 아니라 실제 반복 수요를 확인하는 것이다. 텔레메트리를 넣지 않고 공개 저장소의 지표와 자발적 피드백을 사용한다.

- 사용자가 세션 정리 결과와 재사용 경험을 보고한다.
- 휴지통·복원 안정성에 관한 치명적 데이터 손실 보고가 없다.
- Claude 외 도구 지원, 설치 간소화 또는 자동화에 대한 반복 요청이 발생한다.
- 유지보수 비용보다 실제 사용자 이슈와 기여가 꾸준히 발생한다.

반복 수요가 확인되지 않으면 v0.1을 작은 로컬 도구로 유지하고 제품 범위를 넓히지 않는다.

## 19. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| Claude 내부 저장 형식 변경 | 관대한 파싱, 분석 실패 시 추천 제외, 데이터 접근 로직 집중 |
| 사용자의 삭제 불안 | 기본 미선택, 이유 표시, 사전 확인, 휴지통과 복원 제공 |
| 실행 중 세션 삭제 | 실행 상태 확인과 정리 직전 파일 변경 재검증 |
| 공유 데이터 오삭제 | 소유 관계를 확정하지 못하면 제외, 공유 cache·plan은 범위에서 제외 |
| 정리 중 강제 종료 | manifest 선기록, 원자적 교체, 다음 실행 시 복구 제안 |
| 공식 Claude Code에 동일 기능 추가 | v0.1 범위를 작게 유지하고 실제 수요 확인 후 확장 판단 |
| 시장 수요가 작음 | 오픈소스 TUI로 저비용 검증, 계정·서버·GUI 투자 보류 |

- Homebrew 설치와 자동 업데이트 (npm 배포는 v0.1에서 이미 제공한다)

- 정리 규칙 프리셋
