# sclean v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `~/.claude`에 쌓인 Claude Code 세션을 프로젝트별로 보여주고, 설명 가능한 규칙으로 추천하고, 휴지통 이동·완전 삭제·복원을 트랜잭션으로 수행하는 로컬 전용 Rust TUI를 만든다.

**Architecture:** 순수 코어(스캔·규칙·트랜잭션)와 TUI를 완전히 분리한다. 모든 파일 경로는 `Paths` 한 곳에서만 결정되어 테스트가 임시 디렉터리를 주입할 수 있고(NFR 호환성), Claude JSONL은 스트리밍·조기중단 방식으로 관대하게 파싱해 형식이 바뀌어도 앱이 죽지 않는다. 정리는 `manifest.json` 선기록 → 이동 → 원자적 교체 → 완료 표시 순서의 단일 트랜잭션 경로 하나만 존재하며, 실패 시 역순 롤백한다.

**Tech Stack:** Rust 2024, ratatui + crossterm (TUI), serde/serde_json, rayon (병렬 스캔), chrono (시각 표시), libc (`kill(pid,0)` 실행 감지), tempfile (테스트 fixture)

**Spec:** [docs/PRD.md](../../PRD.md)

## Global Constraints

- 네트워크 요청 금지. HTTP/telemetry 크레이트를 의존성에 추가하지 않는다. (PRD §15 개인정보 보호)
- 로그에 프롬프트 본문을 기록하지 않는다. 로그에는 세션 ID, 경로, 크기, 규칙 이름, 오류 메시지만 남긴다. (PRD §15)
- 프로젝트 소스 경로는 존재 확인(`symlink_metadata`) 외에 읽거나 쓰지 않는다. (FR-16, PRD §12-3)
- 모든 삭제·이동 대상은 실행 직전 `claude_dir` 하위임을 canonicalize로 검증한다. 검증 실패 시 작업 전체를 중단한다. (PRD §15 안정성)
- 시작 시 추천 세션을 자동 선택하지 않는다. (PRD §6 안전 우선)
- 색상은 보조 수단이며 모든 상태는 기호/텍스트로도 구분 가능해야 한다. (PRD §8.5, §15)
- 존재하지 않는 Claude 데이터 경로는 오류가 아니다. (PRD §11.1)
- 기본값: 오래됨 30일, R3/R4/R5 켜짐, R2 켜짐. (PRD §8.4)
- 설정 저장 위치: `~/Library/Application Support/sclean/config.json` (PRD §8.4)
- 데이터 루트: `~/Library/Application Support/sclean/` (`config.json`, `sclean.log`, `trash/`) (PRD §11.2)
- 테스트는 실제 `~/.claude`를 절대 건드리지 않는다. 모든 테스트는 tempdir fixture를 사용한다. (PRD §16)

## 실측한 Claude 데이터 구조 (2026-08-26, macOS)

계획의 근거가 되는 실제 레이아웃. 세션 ID는 UUID이며 `tasks/`·`teams/`는 UUID의 **앞 8자 접두어**로 키를 만든다.

```text
~/.claude/projects/<encoded-cwd>/<uuid>.jsonl      # 세션 대화 기록 (소유: 단독)
~/.claude/projects/<encoded-cwd>/<uuid>/subagents/ # 하위 에이전트 기록 (소유: 단독)
~/.claude/tasks/session-<uuid[0..8]>/              # 작업 데이터 (소유: 접두어 유일할 때만)
~/.claude/teams/session-<uuid[0..8]>/config.json   # 팀 데이터 (소유: 접두어 유일할 때만)
~/.claude/session-env/<uuid>/                      # 세션 환경/훅 스크립트 (소유: 단독)
~/.claude/file-history/<uuid>/                     # 파일 편집 이력 (소유: 단독)
~/.claude/debug/                                   # 이름에 uuid를 포함한 항목만 소유
~/.claude/sessions/<pid>.json, <pid>.<hash>.key    # 실행 중 세션 잠금 (읽기 전용, 삭제 대상 아님)
~/.claude/history.jsonl                            # 공유 기록 (전체 재작성 대상)
~/.claude/todos/                                   # 이 설치에는 없음 — 존재할 때만 <uuid>* 소유
```

**소유권 확정 규칙:** 전체 UUID로 매칭되는 항목만 무조건 소유로 본다. 8자 접두어 키(`tasks/`, `teams/`)는 스캔에서 만든 `prefix -> [session_id]` 맵의 길이가 1일 때만 소유로 인정하고, 2 이상이면 `Blocker::AmbiguousOwnership`를 붙여 해당 세션의 정리를 차단한다. (PRD §9 추천 제외 조건 "연결 데이터의 소유 세션을 확정할 수 없음")

### Task 3: JSONL 관대 파서

**Files:** Create `src/scan/mod.rs`(선언만), `src/scan/jsonl.rs`

**Interfaces:**
- Produces:
  ```rust
  pub struct ParsedInfo {
      pub user_messages: usize,   // isMeta/tool_result 제외한 실제 사용자 턴
      pub tool_uses: usize,
      pub first_prompt: Option<String>,  // 최대 120자, 개행 제거
      pub summary: Option<String>,       // type=="summary" 줄의 summary
      pub cwd: Option<PathBuf>,
      pub is_sidechain: bool,
      pub last_timestamp: Option<i64>,   // epoch seconds
      pub broken_lines: usize,
      pub truncated: bool,               // 조기 중단 또는 바이트 상한 도달
  }
  pub enum Analysis { Parsed(ParsedInfo), Partial(ParsedInfo), Unreadable(String) }
  impl Analysis { pub fn info(&self) -> Option<&ParsedInfo>; pub fn is_usable(&self) -> bool; }
  pub fn analyze(path: &Path) -> Analysis;
  ```

**동작 규약:**
- `BufReader`로 한 줄씩 읽고 각 줄을 개별 `serde_json::from_str::<Value>`로 파싱한다. 실패한 줄은 `broken_lines += 1`로 세고 계속 진행한다. (PRD §14 "JSONL 일부 행이 손상됨")
- 사용자 메시지 판정: `type == "user"` **그리고** `isMeta != true` **그리고** `message.content`가 문자열이거나, 배열이면 `tool_result`가 아닌 블록을 하나라도 포함할 때.
- 도구 사용 판정: `type == "assistant"` 이고 `message.content` 배열에 `type == "tool_use"` 블록이 있을 때.
- 조기 중단: `user_messages > 1 || tool_uses > 0` 이고 `cwd`·`first_prompt`를 이미 확보했으면 즉시 중단하고 `truncated = true`. (R3 판정에 더 읽을 필요가 없음)
- 바이트 상한 `MAX_SCAN_BYTES = 4 * 1024 * 1024`. 초과 시 중단하고 `Partial`을 돌려준다.
- 줄이 하나도 파싱되지 않았거나 파일을 열 수 없으면 `Unreadable`. `broken_lines > 0`이면 `Partial`.
- `Partial`/`Unreadable`은 R3/R4 추천에 쓰지 않는다 (`is_usable() == false`).

- [ ] **Step 1: 실패 테스트** — `src/scan/jsonl.rs` 단위 테스트

**Interfaces:**

- Produces:

  ```rust
  #[derive(Clone, Debug)]
  ```

  ```rust
      pub project_key: String,               // projects/ 아래 디렉터리 이름 (고아는 "__orphan__")

  pub struct Project { pub key: String, pub label: String, pub path: Option<PathBuf>, pub exists: Option<bool>, pub sessions: Vec<Session> }
  ```

### Task 11: 정리 트랜잭션

**Files:** Create `src/ops/cleanup.rs`

**Interfaces:**

**트랜잭션 순서 (PRD §12 그대로 구현):**
1. 각 대상의 모든 연결 파일을 재-stat 해 스캔 시 지문과 비교한다. 다르거나 사라졌으면 그 세션 전체를 `SkipReason::Changed`/`Missing`으로 제외한다. (FR-13)
2. `live.contains(id)`면 `SkipReason::Blocked(Running)`.
3. 남은 모든 경로에 `ensure_within(paths.claude_dir, p)`를 적용한다. 하나라도 실패하면 **작업 전체를 실행하지 않고** 오류를 돌려준다. (FR-16)
4. `trash/<op_id>/` 생성 후 `status: Pending` manifest를 먼저 저장한다.
5. 파일을 `trash/<op_id>/files/<index>/<basename>`으로 이동한다. `index`는 세션 순서 기반이라 이름 충돌이 없다.
6. `history::plan_removal` + `apply`.
7. 성공 시 manifest를 `Complete`로 갱신한다.
8. `mode == Trash`면 종료.
9. `mode == Permanent`면 `trash/<op_id>` 폴더 전체를 삭제한다.

**롤백:** 5·6단계 실패 시 이미 이동한 파일을 역순으로 원위치에 되돌리고, history 백업을 복원하고, manifest를 `RolledBack`으로 표시한다. 롤백까지 실패하면 manifest를 `Failed`로 남기고 로그에 기록한다(다음 실행에서 복구 화면이 뜬다). (FR-14, §12)

**테스트용 실패 주입:** `execute`는 내부적으로 `move_path`를 함수 포인터로 받는 `execute_with(mover: &dyn Fn(&Path,&Path)->io::Result<()>, ...)`에 위임한다. 테스트는 N번째 이동에서 실패하는 mover를 주입한다.
