# sclean v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local macOS TUI that discovers Claude Code sessions, explains rule-based cleanup recommendations, and safely trashes, permanently deletes, restores, or purges selected sessions.

**Architecture:** A small Rust binary keeps Claude storage parsing, recommendation rules, transactional file operations, and terminal presentation separate. All destructive work is planned from a read-only snapshot, staged under the app trash with a manifest, and revalidated immediately before mutation. The TUI calls these tested domain functions and never manipulates Claude files directly.

**Tech Stack:** Rust 2024 edition, ratatui 0.30.2, crossterm 0.29.0, serde 1.0.229, serde_json 1.0.151, Rust standard library tests.

**Spec:** `docs/PRD.md`

## Global Constraints

- v0.1 targets Claude Code data on macOS and runs entirely locally.
- `sclean` opens one keyboard-driven TUI; there are no cleanup subcommands.
- No network calls, telemetry, AI classification, scheduler, native GUI, or non-Claude backends.
- Recommendations never preselect sessions and always include human-readable reasons.
- No project source file may be mutated.
- Unknown or malformed Claude data is displayed conservatively and excluded from recommendation.
- Destructive operations revalidate the scan snapshot and use an app-owned trash manifest for rollback and restore.
- Tests use temporary fixture directories and never the real `~/.claude` directory.

**Interfaces:**

- Produces: `CleanupPlan { operation_id, entries, total_bytes }`

- Produces: `execute_cleanup(plan: &CleanupPlan, mode: CleanupMode) -> Result<CleanupReport, CleanupError>`
- Produces: `list_trash(app_dir: &Path) -> Result<Vec<TrashOperation>, CleanupError>`
- Produces: `restore(operation: &TrashOperation, selected_ids: &HashSet<String>) -> Result<CleanupReport, CleanupError>`
- Produces: `purge(operation: &TrashOperation, selected_ids: &HashSet<String>) -> Result<CleanupReport, CleanupError>`

- [ ] **Step 1: Write failing transaction tests**

Use a temporary Claude root and app root. Assert trash moves a transcript and a session-owned task file, writes `manifest.json`, and never touches a sentinel file in the source project:

```rust
let report = execute_cleanup(&plan, CleanupMode::Trash).unwrap();
assert_eq!(report.completed_sessions, 1);
assert!(!transcript.exists());
assert_eq!(fs::read_to_string(source_sentinel).unwrap(), "keep");
```

Add tests for snapshot-change rejection, restore without overwrite, purge, and rollback when a planned source disappears midway.

- [ ] **Step 2: Run cleanup tests and verify RED**

Run: `cargo test cleanup::tests -- --nocapture`

Expected: compilation fails because cleanup planning and execution APIs do not exist.

- [ ] **Step 3: Implement manifest-first staging**

Validate every source path is under the supplied Claude root. Recheck size and modified timestamp before moving. Create `<app_dir>/trash/<operation-id>/manifest.json` before mutation, preserve original paths in manifest entries, move session-owned files into `files/`, and update manifest status after success.

For `history.jsonl`, preserve malformed lines, remove only parsed records whose exact session ID matches a selected session, write through a sibling temporary file, then atomically replace the original. Store the removed records in the manifest; restoration appends only records whose session ID is not currently present. Keep a full pre-edit copy until the transaction completes so rollback can restore it byte-for-byte.

For permanent mode, complete the same staging transaction and remove the finished operation directory. On any staging failure, move completed entries back in reverse order and restore the shared-history backup. Restoration refuses any occupied destination. Purge removes only files named by a completed manifest.
